# 地区优先的代理分流脚本

用于支持 JavaScript 配置覆写的代理客户端。脚本基于订阅节点生成地区策略组，并设置 DNS、应用分流和网络参数。

> 脚本需要运行在提供 `main(config)` 配置入口的客户端中，不能直接作为 YAML 配置导入。实际兼容性取决于客户端及代理内核支持的字段、正则表达式和 Geo 数据。

## 功能介绍

- 自动读取 `proxies` 和 `proxy-providers`，过滤名称含流量、到期、订阅、官网、客服等关键词的节点。
- 为所有节点及各地区生成自动测速、故障转移、哈希均衡三种策略。
- 为 AI、X、Google、YouTube、Telegram 和苹果服务提供独立选择组。
- 使用 Fake-IP DNS，默认关闭 IPv6，并启用 TCP 并发与连接保活。
- 没有可用节点且未配置 provider 时，选择组回退到直连。

## 地区分组

按以下顺序匹配，同一节点只进入优先级最高的一个地区组：

| 优先级 | 分组 |
| --- | --- |
| 1：独立国家／地区 | 香港、台湾、新加坡、日本、韩国、美国、俄罗斯 |
| 2：次区域 | 东南亚、南亚、中亚、中东 |
| 3：洲级分组 | 欧洲、北美、南美、非洲、澳洲（大洋洲） |
| 4：兜底 | 其他 |

例如：美国节点优先进入美国组；俄罗斯节点优先进入俄罗斯组；马来西亚节点进入东南亚组。已移除中东规则中容易误匹配“马来西亚”的独立“西亚”关键词。

优先级通过后续分组的 `exclude-filter` 实现。互斥范围仅限地区组；节点仍会出现在所有节点策略组，以及启用了 `include-all` 的手动选择组中。

地区判断依据节点名称中的国家名、城市名、国家代码和国旗，不查询节点 IP 的实际地理位置。当前保留土耳其归欧洲、埃及归非洲的分类方式。

中东组包含：阿联酋、沙特阿拉伯、卡塔尔、科威特、巴林、阿曼、也门、约旦、黎巴嫩、伊拉克、叙利亚、伊朗、以色列、巴勒斯坦。

## 策略与测速

| 策略 | 行为 |
| --- | --- |
| 自动测速 | `url-test`，按延迟选择节点，容差为 100 ms |
| 故障转移 | `fallback`，按候选顺序选择可用节点 |
| 哈希均衡 | `load-balance`，使用 `consistent-hashing` 策略分配连接 |

测速地址为 `http://cp.cloudflare.com/generate_204`，间隔 600 秒，超时 5000 ms；启用懒测速，最大失败次数为 3。实际触发方式与故障判定由内核决定。

仅使用静态节点时，没有匹配节点的地区组不会生成；存在 provider 时，会预先生成全部地区组及其他组，便于 provider 更新后参与匹配，因此可能看到空组。

## 分流规则

规则自上而下匹配：

1. 私有域名、私有 IP 和 `vidhub1.cc` 直连。
2. 苹果服务进入苹果组，该组默认首选 `DIRECT`。
3. OpenAI、Claude、Gemini 的指定域名，以及 Perplexity、Poe、Grok 等进入 AI 组。
4. X／Twitter、YouTube、Telegram、Google 分别进入对应应用组。
5. `geolocation-!cn` 进入代理组，国内域名与中国 IP 直连。
6. 其余流量进入代理组。

AI 规则为脚本中列出的域名清单，不保证覆盖所有 AI 服务及其依赖域名。Gemini 的专用域名规则优先于通用 Google 规则。

## DNS 与网络设置

- 本地 DNS：`114.114.114.114`、`223.5.5.5`。
- 有节点或 provider 时，普通解析默认使用 `https://1.1.1.1/dns-query#代理`；否则使用本地 DNS。
- 国内域名使用本地 DNS，私有域名使用系统 DNS；代理服务器域名和直连解析使用本地 DNS。
- Fake-IP 地址池：`198.18.0.1/16`，监听 `127.0.0.1:1053`。
- 对局域网、时间同步、网络连通性检测及部分 STUN 域名设置 Fake-IP 例外。
- 关闭 IPv6，启用 TCP 并发、统一延迟和连接保活。
- 保存策略组选择和 Fake-IP 缓存；保活空闲时间 30 秒，间隔 15 秒。

## 使用方式

1. 备份原配置及原覆写脚本。
2. 在客户端中添加订阅或配置节点／provider。
3. 将 `地区优先分组.js` 的完整内容放入客户端的 JavaScript 覆写入口。
4. 应用并重新加载配置，检查日志和策略组。
5. 根据需要为各应用选择地区或节点；苹果组可切换为代理。

本脚本不包含订阅地址、代理账号或节点凭据，不能单独提供代理连接。

## 注意事项

### 会覆盖原有设置

脚本会替换原有 `dns`、`proxy-groups` 和 `rules`，删除 `rule-providers`，并修改部分网络参数。原有自定义策略组、分流规则和外部规则集不会保留；需要保留的内容应合并到脚本中。

### 名称匹配存在局限

节点同时包含多个地区信息时，按优先级归组，不一定代表实际出口。例如，节点名中的中转地也可能参与匹配。

互斥机制解决重复归组，不能消除所有关键词误判。短国家代码、英文名称子串以及订阅商的自定义命名仍可能导致分类偏差。节点过滤关键词也可能误排正常节点，例如名称中含 `Premium` 的节点。

脚本在检查静态节点时使用 JavaScript 不区分大小写匹配；实际策略组的 `filter` 与 `exclude-filter` 由客户端／内核执行，大小写行为应以实际运行结果为准。

### 依赖客户端和内核能力

需要支持 `include-all`、`exclude-filter`、对应策略类型及 DNS 等字段。其他组的正则包含负向前瞻，应确认内核支持该正则语法。

`GEOSITE` 和 `GEOIP` 规则需要相应数据可用，包括 `apple`、`twitter`、`youtube`、`telegram`、`google`、`geolocation-!cn`、`cn` 等分类。缺少数据或字段不受支持时，可能加载失败或行为不符合预期。

### 检查 provider 与空组

脚本将“配置了 provider”视为有节点来源，并不会验证 provider 是否成功下载或包含可用节点。provider 为空、更新失败或地区无匹配节点时，请检查日志及组内候选列表。

### DNS 与连通性

远程 DoH 使用 `#代理` 指定代理组，需要客户端支持该写法且代理组能够连通。脚本设置 `respect-rules: false`，不要将其理解为全部 DNS 请求都按流量分流规则执行。

测速通过只表示节点能访问测速地址，不能证明 AI、流媒体等服务可用。哈希均衡也不保证每个节点流量相等；对出口 IP 稳定性敏感的服务，可手动选择固定节点。
